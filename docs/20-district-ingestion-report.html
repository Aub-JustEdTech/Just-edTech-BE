✅ Fixed this session

Three infra bugs found and fixed while getting chunk classification (Step 3) working end-to-end at real volume.

Fixed heatmap_aggregate.id had no real IDENTITY

The model declared Identity() on heatmap_aggregate.id, but the migration that created the table never added the Postgres-side sequence — every insert hit NotNullViolationError. This is what silently blocked the first attempt to apply the 8,099-chunk batch. Fixed with a targeted migration adding GENERATED BY DEFAULT AS IDENTITY; verified live.

Fixed apply_batch_results rolled back everything on one bad row

The apply step classified all 8,099 chunks correctly, then hit the bug above on a single heatmap_aggregate row — and because it committed once at the very end, that one failure erased every chunk's progress, leaving all 8,099 stuck at status=submitted with no automatic retry. Hardened with incremental commits every 200 chunks, a Qdrant timeout increase + retry-with-backoff on set_payload, and an isolated try/except around the aggregate step so it can no longer take the whole batch down with it.

Fixed celery-beat re-fired an unapproved batch on restart

celery-beat's schedule state lived only in the container's writable layer. A routine restart made it treat the daily submit job as overdue and fire it immediately — auto-submitting all 8,099 pending chunks (≈$1.63) without the planned cost approval step. Fixed by mounting a persistent volume for the schedule file, so future restarts remember what already ran today.
